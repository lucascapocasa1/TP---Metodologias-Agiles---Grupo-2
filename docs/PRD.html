1. Introducción

1.1 Propósito del documento

Este PRD define qué debe hacer el Sistema Kiosco: usuarios, alcance, requerimientos funcionales y no funcionales, criterios de aceptación y restricciones. Es la referencia de producto contra la cual se valida lo que se entrega sprint a sprint. El cómo (stack, modelo de datos, endpoints, decisiones de diseño) está en el ARD.

1.2 Contexto y problema

Un kiosco de barrio necesita digitalizar su operación diaria: hoy la gestión de productos, precios y cobros se hace de forma manual o con planillas, lo que provoca:

  • Errores de precio y falta de control sobre quién modificó qué.
  • Sin registro de quién atendió la caja ni de qué se vendió.
  • El dueño no tiene visibilidad de stock ni de lo que más se vende.
  • Cualquier empleado podría entrar a la parte sensible del negocio (costos, reportes) si no hay control de acceso.

WebhookAviso que Mercado Pago envía al sistema cuando cambia un pago; el sistema no confía en el aviso y vuelve a consultar el pago a la API
OAuth (conectar Mercado Pago)Autorización de la cuenta del negocio: el dueño toca "Conectar", autoriza en Mercado Pago y el sistema guarda las credenciales para cobrar a esa cuenta
Modo de prueba (QR)Sin credenciales de Mercado Pago, el QR abre una pantalla de pago simulado del propio sistema, sin plata real
Pantalla del cliente (display)Vista en un celular del mostrador que muestra el QR del cobro y se actualiza sola al aprobarse el pago
ResendServicio de envío de correo usado para la recuperación de contraseña; en desarrollo, sin API key, el mail se imprime en la consola
PublicaciónDespliegue del sistema en un hosting (Render) con `DEBUG=False`, `SECRET_KEY` propia y base PostgreSQL
AuditoríaRegistro inmutable de acciones relevantes (usuario, acción, fecha, IP)
SprintIteración con entrega demostrable (4 sprints planificados + consignas nuevas de la cátedra)

2.3 Restricciones

  • Entregas fijas: Sprint 1 (24-09) OK · Sprint 2 (01-10) OK · Sprint 3 (15-10) OK · Sprint 4 (05-11) OK.
  • Aplicación web (navegador), sin app nativa; se usa en PC del kiosco y eventualmente en celular/tablet.
  • Trabajo en equipo con merge a `main`; los artefactos deben poder integrarse sin romper los tests existentes (379 en verde).
  • Idioma y formato argentinos: español rioplatense, moneda ARS, horario `America/Argentina/Buenos_Aires`.
  • El servidor de desarrollo corre en el puerto 8001 (conservar ese puerto en todas las máquinas del equipo).
  • Dependencias externas: PostgreSQL como base principal; Mercado Pago para el cobro con QR (sin credenciales se degrada a modo de prueba) y Resend para el correo (sin API key se imprime en la consola). El sistema no debe romperse si esas credenciales faltan.
  • Publicación: Render con plan gratis; el sitio "duerme" sin uso y la base gratuita vence a los 30 días.
